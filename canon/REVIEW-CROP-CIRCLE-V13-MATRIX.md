## 第一節：分層裁示 — 全部採納

這一輪提出的 diff 解決了正典裡累積最久的三個結構性缺陷。逐條記錄。

### 1.1 OPEN ISSUE 1 已關閉：O1 與 r_isco 分離

```
- L1 = 第一軌道 O1, r_isco (6M, 非零)
+ O1 := 0                # 邏輯原點，宣告層
+ r_isco_phys := 6M      # 物理第一穩定軌道，非零，不等於 O1
+ L1 := r_isco_phys      # 不再等同 O1
```

**採納。** 原本的衝突是：`canon/UNICODE-ORIGIN-DECLARATION` 宣告層寫 `O1 = 0`、
而 `PASTEABLE-FORMAL-V13.1` 寫 `L1 = O1 = r_isco = 6M`。兩者互斥。

分離後：`O1` 專屬邏輯原點層，`r_isco_phys` 專屬物理層。**OPEN ISSUE 1 關閉。**

注意：此 patch 的目標檔 `canon/ORIGIN-FIELD-THEORY-v0.7.2.md` **目前不在 `main`**，
仍在分支 `feature/canon-origin-field-theory-v0.7.2`。該分支併入 main 時必須同時套用此 patch，
否則正典會回退到舊的互斥定義。**列為待辦，不得遺漏。**

### 1.2 「索引層 不等於 X 層」病灶：第三次復發，這次被正面處理

```
+ 5_value := 5
+ 5_mod5  := 0   # 5 = 0 (mod 5) 標籤層，明文標註
+ 5_mod3  := 2   # 5 mod 3 = 2 核九格層
+ # 分層後 0=5 矛盾解除，mod 3 與 mod 5 不得互證
```

**採納。** 兩個算術值都對：`5 mod 5 = 0`、`5 mod 3 = 2`。
關鍵是最後那行禁令 —— **mod 3 與 mod 5 不得互證**。這正是需要的。

此病灶的三次復發，現在可以合併成一條規則：

| 次 | 形式 | 處理 |
| --- | --- | --- |
| 1 | 索引層 不等於 矩陣層（`det(L0) = 360 = 0 mod 3`，K-07） | 已內化 |
| 2 | 特徵 3 不等於 特徵 0（`exp(Q)` 屬於 `SU(2)`） | PR #7 已記 |
| 3 | 索引 5 不等於 座標 0（`5_value` 對 `5_mod5`） | 本輪關閉 |

**通則：任何等號都必須標明它活在哪一層。跨層等號一律視為型別錯誤。**

### 1.3 其餘三條

- **補回 `3 對 7`** — 採納。核九格四組完整，與 `verify_v13_pairing.py` 已驗的「配對數 = 4」一致。
- **選路作廢** — 採納。`8` 落在 7 個頂點之外，原序列無法對照到 W6 上。
- **`L0` 不屬於 `GL(3,F3)`** — 這條本來就已由 K-07、K-08 機器驗過（`det = 360 = 0 mod 3`）。重申無誤。

### 1.4 一處型別仍需修

```
+ C0_value := 5 in F3^9
```

**這行不對。** `F3 = 0, 1, 2`，**5 不是 `F3` 的元素**（5 mod 3 = 2 才是）。
而 `F3^9` 是 9 維向量空間，5 是一個純量索引，不是 9 維向量。

建議改為：`C0_index := 5`，屬於索引集 `1..9`。
數值上若要進 `F3`，則寫 `C0_residue := 5 mod 3 = 2`。

## 第二節：矩陣本身 — 四項宣稱的審查

### 2.1 可以先確認的結構性事實（手算，已寫入 fixture 作為 assert）

- **M 對稱。** 逐格核對過，`M[i][j] = M[j][i]` 全部成立。
- **對角線全為 2。** 因為 `2 = -1 mod 3`，所以 `M = A - I`，其中 `A` 是一個 13 點簡單圖的鄰接矩陣。
  這是個好性質：整個問題化約成「1 是否為 `A` 在 `F3` 上的特徵值」。
- **邊數 26，度數序列 `3,3,3,3,8,4,4,4,4,4,4,4,4`。**
- **中樞 v5 度數 8**，連到全部其他核格，且與 PUB 完全無邊。

### 2.2 宣稱 2 `core_sum = 10` — **不成立**

| 量 | 值 |
| --- | --- |
| 核塊行和（僅第 1-9 欄） | `4,4,4,4,10,4,4,4,4` |
| 全行和（13 欄） | `5,5,5,5,10,6,6,6,6,6,6,6,6` |
| 對位全行和 `row1 + row9` | **11** |
| 對位核塊和 `row1 + row9` | **8** |

無論怎麼算，**都不是 10**。唯一得到 10 的是中樞行 `row5` 的核塊和。

索引層的 `i + i' = 10` 當然仍然成立 —— 但那是索引，不是矩陣。
這條宣稱把索引層的性質說成矩陣層的性質，是 §1.2 那個病灶的**第四次**出現。

### 2.3 宣稱 3 中樞行「恆 = 5」 — **不成立**

`row5 = [1 1 1 1 2 1 1 1 1 | 0 0 0 0]`，核塊和 = `8 * 1 + 2 = 10`。

**不是 5，是 10。** 而 10 恰好就是對位和 —— 所以註解寫錯了，但數字其實比註解更好。
建議改註解為「中樞行核塊和 = 10 = 對位和」。

### 2.4 第三條合法棲息 — **FAIL**

PUB 子矩陣（第 10-13 行列）：

```
[2 0 1 0]
[0 2 0 1]
[1 0 2 0]
[0 1 0 2]
```

重排索引為 `(10,12)` 與 `(11,13)` 兩組後，它是兩個相同 2x2 的直和：

```
[[2, 1], [1, 2]]
```

而 `det([[2,1],[1,2]]) = 4 - 1 = 3 = 0 mod 3`。

所以 **`pub_det = 0 * 0 = 0 mod 3`**。

HEARTBEAT-V13 的三條合法棲息是：

1. `det(M) != 0 mod 3`
2. `core_sum == 10`
3. `pub_det != 0 mod 3`

**第三條 FAIL。** 而且第二條依 §2.2 也 FAIL。

這一點很重要，因為 `verify_v13_pairing.py` 已經用 13-循環置換驗過
「full_det 不為 0 但 pub_det 為 0」是**可能的** —— 三條是獨立的。
所以即使全矩陣 det 真的等於 1，**這個矩陣仍然不是合法棲息。**

### 2.5 對位守恆 — **FAIL**

這是本輪最深的一處問題。

對位置換 `P` 要求 `P M P = M`。必要條件之一是 `deg(i) = deg(i')`。但：

| 對位 | 度數 |
| --- | --- |
| `1 對 9` | 3 對 **4** |
| `2 對 8` | 3 對 **4** |
| `3 對 7` | 3 對 **4** |
| `4 對 6` | 3 對 **4** |

根因：**核 1-4 每列只有 1 條 PUB 連線，核 6-9 每列有 2 條。**

- `N(1) = 5, 9, 10`
- `N(9) = 1, 5, 12, 13`

`P` 會把 `N(9)` 映到 `9, 5, 11, 10`，但實際 `N(1)` 是 `5, 9, 10` —— 多出一個 `11`。

**所以這個矩陣打破了它自己聲稱要編碼的對位律。**
它在核塊內部確實對稱（每個對位的 2x2 對角塊都是 `[[2,1],[1,2]]`），
但在 Core 到 PUB 的耦合上系統性地不對稱。

順帶一提：核塊內每個對位的 2x2 塊也是 `[[2,1],[1,2]]`，`det = 0 mod 3`。
也就是說**每一組對位的局部 2x2 在 F3 上都是退化的**。這是刻意還是意外，需說明。

### 2.6 宣稱 4 `PUB 交 Core = 空集` — **成立，但只在索引集層**

`1..9` 與 `10..13` 當然不交。這條是真的，型別也對。

但 `M` 有 Core 到 PUB 的非零耦合（例如 `M[1][10] = 1`），**所以 M 不是分塊對角矩陣**。
索引集分離 **不等於** 子空間分離。這兩件事不得互相背書。

### 2.7 宣稱 1 `det(M) = 1 mod 3` — **PENDING，我不猜**

13x13 的 `F3` 行列式，我不手算，也不宣稱。

fixture 的第七節會算出來並列印，**但不 assert**。那次執行就是首次機器測定。
依 `tools/README.md` 規則第 7 條，我的預測欄位明文寫 `UNKNOWN`，而不是填一個好看的數字。

有一個提示但不構成證明：`M = A - I`，所以 `det(M) = 0` 等價於「1 是 A 在 F3 上的特徵值」。
又 `A` 的全一向量作用結果是度數向量 `(0,0,0,0,2,1,1,1,1,1,1,1,1) mod 3`，不等於全一向量，
所以**全一向量不是** 特徵值 1 的特徵向量。這只排除了一個候選，什麼都沒證明。

## 第三節：麥田圈對應 — SYMBOLIC，不可升格

```
# 中心菱形 = C0=5, 左右雙渦 = 1 對 9, 外環 = PUB
```

這三行是**圖形詮釋**，不是可驗命題：沒有給出從麥田圈影像到矩陣索引的映射函式，
所以沒有任何東西可以被檢查或被否證。

**CLAIM CEILING = `SYMBOLIC`。** 不得升格為 `FORMAL_MODEL`，除非提供：

1. 影像的形狀分解（幾個瓣、幾環、對稱群）
2. 從形狀到 `1..13` 的明確賦號規則
3. 該賦號在對位置換下的行為

沒有這三項，「對應圖中結構」只是命名，不是建模。

## 第四節：結論

| 宣稱 | 判定 |
| --- | --- |
| M 對稱、對角全 2、`M = A - I` | 成立（手算，fixture 已 assert） |
| 宣稱 1 `det(M) = 1 mod 3` | **PENDING** — 待機器測定，我拒絕手猜 |
| 宣稱 2 `core_sum = 10` | **FAIL** — 實際行和 5/6/10，對位和 11 或 8 |
| 宣稱 3 中樞行「恆 = 5」 | **FAIL** — 實際核塊和 = 10 |
| 宣稱 4 `PUB 交 Core = 空集` | 成立，但僅索引集層；M 非分塊對角 |
| 第三條 `pub_det != 0` | **FAIL** — `pub_det = 0 mod 3` |
| 對位守恆 `P M P = M` | **FAIL** — 對位兩端度數 3 對 4 |
| 麥田圈對應 | `SYMBOLIC` |
| 分層裁示 diff（O1、mod、3對7、選路） | **全部採納** |

**總結一句：分層裁示這一半全對，矩陣這一半有四處 FAIL。**

矩陣要成為合法棲息，至少要修好兩件事：

1. **PUB 4x4 不能用 `[[2,1],[1,2]]` 這種塊** —— 它在 `F3` 上退化。
   換成例如 `[[1,1],[1,2]]`（`det = 1`）或 `[[0,1],[1,0]]`（`det = -1 = 2`）。
2. **Core 到 PUB 的耦合必須對位對稱** —— 若 `i` 連到 PUB 的 `p`，則 `i'` 必須連到 `P(p)`。
   目前 1-4 各 1 條、6-9 各 2 條，這條就斷了。

修好後重跑 fixture。**在 fixture 出綠燈之前，這個矩陣不得寫進 `kernel/`。**
